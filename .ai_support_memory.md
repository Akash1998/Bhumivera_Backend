# Bhumivera Autonomous AI Customer Support Engine — Architecture & Memory Ledger (`.ai_support_memory.md`)

## 1. Full Repository Topology Map

### 1.1 Backend (`Bhumivera_Backend` — Node.js / Express on Railway)
- **Entrypoint & Runtime (`server.js`)**:
  - Express 5 application configured with `trust proxy = 1`, `createRequestObservability()`, `clientContextMiddleware()`, strict origin-validated CORS (`FRONTEND_ORIGINS` + `ALLOWED_NATIVE_ORIGINS`), Content-Security-Policy (CSP), `/health` readiness check (`databaseReady`), `/api/webhooks/razorpay` raw webhook router, `express.json({ limit: '10kb' })`, `normalizeErrorResponses`, `redisResponseCache`, and `createModuleAvailabilityMiddleware` per domain module.
  - Runs automatic sequential database migrations on boot via `runMigrations(pool, migrations)`.
- **Configuration (`config/`)**:
  - `config/db.js`: `mysql2/promise` connection pool (`DB_POOL_SIZE` default 3, `connectTimeout: 10000`, TLS `rejectUnauthorized: true` unless `DB_SSL=false`).
  - `config/environment.js`: Validates production secrets (`JWT_SECRET`, `OTP_SECRET`, `CARRIER_CREDENTIALS_KEY`, `RAZORPAY_*`) and origin lists.
  - `config/s3Upload.js`: Cloudflare R2 / S3 presigned upload URL generator (`generateUploadUrl`) used for product media, review photos, and return evidence photos (`returns/{userId}/{filename}`).
- **Middleware (`middleware/`)**:
  - `middleware/authMiddleware.js`:
    - `authenticateUser`: Validates `Authorization: Bearer <jwt>`, checks active session via `isSessionActive(payload, req)` in `utils/sessionStore.js`, and verifies `users.is_active = 1`.
    - `authenticateAdmin`: Validates admin JWT, checks `ROLE_PERMISSIONS` (`superadmin`, `admin`, `warehouse_admin`) against route-level `ADMIN_PERMISSION_ROUTES`, and enforces refund/fulfillment role constraints.
  - `middleware/rateLimiter.js`:
    - IPv4/IPv6-aware rate limiting (`getLoginIpKey` with `/56` subnet normalization for IPv6, `accountNetworkKey` combining IP + SHA-256 email hash).
    - Uses `rate-limit-redis` when `RATE_LIMIT_REDIS_URL` / `REDIS_URL` is configured, falling back to in-memory store.
  - `middleware/clientContext.js`, `middleware/redisResponseCache.js`, `middleware/requestObservability.js`.
- **Models (`models/`)**:
  - `userModel.js`: `users`, `user_sessions`, `admin_sessions`, `trusted_devices`, `pending_registrations`, `otp_attempts`, `password_history`.
  - `orderModel.js`: `orders`, `order_items` — handles transactional order creation, stock deduction, loyalty point earning/redemption/reversal, referral wallet debits, shopping wallet rewards, and `updateOrderStatus` with `assertOrderStatusTransition`.
  - `returnModel.js`: `returns` — enforces delivered status check, duplicate return prevention, RMA generation (`RMA-XXXXXXXX`), and status progression (`pending_admin_review` -> `return_in_progress` -> `received` -> `refund_pending` / `refunded` / `replacement_sent` / `rejected`).
  - `returnRefundModel.js`: `return_refund_requests` — tracks Razorpay refund attempts (`attempt_no`, `receipt`, `payment_id`, `provider_refund_id`, `amount_paise`, `status`).
  - `productModel.js`: `products`, `product_images` — manages catalog items, stock (`quantity`), pricing (`price`, `discount_price`), `specifications` JSON, `warranty_period`, `tags`, and R2/CloudFront image URLs.
  - `shippingModel.js` & `shippingLabelModel.js`: `shipping_zones`, `shipping_carrier_accounts`, `shipping_labels`, `shipping_label_events` (Shiprocket, Delhivery, BlueDart).
  - `contactModel.js`: `support_tickets`, `support_ticket_messages`.
  - `notificationModel.js`: `notifications` (user-scoped and global system/admin alerts).
  - `settingsModel.js`: `settings` key-value configuration store (`return_policy_days` default `7`, `free_shipping_threshold` default `500`, `standard_charge` `50`, `express_charge` `150`).
- **Services & Utilities (`services/`, `utils/`)**:
  - `services/returnRefundService.js`: Idempotent Razorpay refund initiation (`createReturnRefund`) and reconciliation (`reconcileReturnRefund`).
  - `services/shippingPolicy.js`: Calculates standard vs. express shipping charges (`PREMIUM_DELIVERY_THRESHOLD = 799`, `PREMIUM_DELIVERY_SURCHARGE = 100`).
  - `services/vectorService.js`: Local HuggingFace MiniLM embedding + Pinecone semantic product search (`performSemanticSearch`).
  - `utils/mail.js`: HTTPS REST email dispatch via Mailrelay (`sendMail`, `sendOrderStatusEmail`) with Bhumivera HTML branding.
  - `routes/supportRoutes.js`: Support portal endpoints (`/api/support/login`, `/me`, `/agents`, `/customers`, `/tickets`) using `support_agents` table and `scope: 'support-agent'` JWTs.
  - `routes/aiRoutes.js`: Admin product copy generation using `@google/genai` (`gemini-2.5-flash`) with strict factual compliance guardrails.

### 1.2 Frontend (`Bhumivera_Frontend` — React 18 + Vite + Tailwind CSS on Vercel)
- **App Shell & Routing (`src/App.jsx`)**:
  - Wraps app in `BrowserRouter` -> `ToastProvider` -> `AuthProvider` -> `CartProvider` -> `WishlistProvider` -> `CompareProvider`.
  - Distinguishes customer storefront (`!isManagementView`) from management portals (`/admin`, `/warehouse`, `/support`, `/mpgebusiness`).
  - Renders `<Navbar />`, `<NetworkStatus />`, `<Routes />`, `<MobileBottomNav />`, `<Footer />`, and `<MiniCart />`.
- **State Contexts (`src/context/`)**:
  - `AuthContext.jsx`: Manages customer (`localStorage.getItem('token')`), admin (`adminToken`), and warehouse (`warehouseToken`) sessions; exposes `{ user, token, isAuthenticated, loading, login, logout, updateUser }`.
  - `CartContext.jsx`: Synchronizes server cart (`/api/cart`) for authenticated customers and `localStorage.getItem('Bhumivera_guest_cart')` for guests; exposes `{ cart, isCartOpen, setIsCartOpen, addToCart, rulePreview, loyalty }`.
  - `ToastContext.jsx`: Provides `useToast()` (`success`, `error`, `info`, `warning`, `showToast`) and listens to `window` `'operation-feedback'` events.
- **API Client (`src/services/api.js`)**:
  - Axios instance pointed at `${BASE_URL}/api` with automatic Bearer token injection, 401 token refresh (`POST /api/auth/refresh`), offline catalog fallback, and mutation toast notifications (`notify: false` opt-out supported).
- **Existing Support & Order Views**:
  - `src/components/SupportCenter.jsx`: Profile tab ticket form and FAQ accordion.
  - `src/pages/SupportPortal.jsx`: Staff support portal at `/support`.
  - `src/pages/OrderTracking.jsx`: Visual 5-step order progress tracker (`pending/placed` -> `confirmed` -> `packed` -> `shipped` -> `delivered`).
  - `src/pages/Returns.jsx` & `src/pages/ReturnsCentre.jsx`: Customer return submission and policy guide.
  - `src/utils/deliveryEstimate.js`: IST (UTC+5:30) 14:00 dispatch cutoff calculator (4–6 days before 14:00 IST, 5–7 days after).

## 3. Authentication, Security & Rate-Limiting Architecture

1. **Dual-Mode Support Authentication (`optionalAuthenticateUser`)**:
   - Logged-in customers send `Authorization: Bearer <token>`. The support controller validates the JWT and active session via `isSessionActive`, binding `req.user` (`id`, `email`, `role`) to the support session so order lookups, cancellations, and returns execute seamlessly on owned orders.
   - Guest users can initialize a chat session without a JWT (`req.user = null`) and look up orders by providing both `order_number` (or `order_id`) AND matching `email` or `phone` from `users` / `orders.address_snapshot` (preventing unauthorized enumeration of other customers' orders).
   - Self-service mutating operations (order cancellation, return/replacement initiation) require either an authenticated session owning the order OR verified guest order+email/phone ownership match.
2. **Rate Limiting (`middleware/rateLimiter.js`)**:
   - `supportChatLimiter`: 30 messages per 5 minutes per IP/account key (`SUPPORT_CHAT_RATE_LIMIT`) to prevent LLM token exhaustion and DDoS abuse.
   - `supportSessionLimiter`: 20 session initializations per 15 minutes per IP (`SUPPORT_SESSION_RATE_LIMIT`).
   - `supportEscalationLimiter`: 5 escalations per 15 minutes per IP (`SUPPORT_ESCALATION_RATE_LIMIT`).
3. **Strict PII Masking (`utils/piiMasker.js`)**:
   - All user and assistant messages persisted to `ai_support_messages`, logged to console, or dispatched via webhook escalations pass through `maskPII(text)` and `sanitizeObjectPII(obj)`:
     - Redacts 13–19 digit payment card numbers (Luhn/pattern match) -> `[REDACTED_CARD]`.
     - Redacts CVV/CVC patterns -> `[REDACTED_CVV]`.
     - Redacts passwords, PINs, OTPs, and secret keys -> `[REDACTED_SECRET]`.
     - Redacts JWTs (`eyJ...`) and Bearer/API tokens -> `[REDACTED_TOKEN]`.
     - Redacts Indian Aadhaar (12-digit) / PAN patterns when shared in chat -> `[REDACTED_GOV_ID]`.

- **Icons & Motion**:
  - `lucide-react` icons, smooth CSS transitions & `framer-motion` micro-interactions.
- **Mounting & Z-Index Strategy**:
  - Mounted in `src/App.jsx` inside `AppContent` whenever `!isManagementView` is true.
  - Positioned at `bottom-20 right-4 md:bottom-6 md:right-6 z-[250]` so it never collides with `<MobileBottomNav />` on mobile viewports or Toast notifications (`z-[9999]`).
