## 2. Tamper-Proof Coupon & Promotion Architecture (Better than Amazon / Flipkart)

### 2.1 Unified Coupon Schema (`coupons` Table)
All coupon sources (Admin Panel, Spin-the-Wheel Gamification, Abandoned Cart Recovery, Referral Rewards, and Support Courtesy Coupons) share a unified, bidirectional schema in `models/couponModel.js`:
- `code` (`VARCHAR(64) UNIQUE`): Normalized uppercase code.
- `discount_type` (`ENUM('percentage','fixed')`) & `discount_value` (`DECIMAL(10,2)`).
- `min_order_amount`, `min_order_value`, `minimum_order_amount` (`DECIMAL(10,2)`): Automatically synchronized on insert/update and read via `COALESCE(min_order_amount, min_order_value, minimum_order_amount, 0)`.
- `max_discount_amount` (`DECIMAL(10,2)`): Optional cap for percentage discounts.
- `usage_limit` (`INT`): Global maximum total redemptions across all users (`NULL` = unlimited global pool).
- `per_user_limit` (`INT NOT NULL DEFAULT 1`): Strict per-customer usage cap. Defaults to **`1` (one redemption per user)** so a customer can never reuse the same coupon 10+ times even when `usage_limit` is high or unlimited.
- `used_count` (`INT NOT NULL DEFAULT 0`): Atomic global redemption counter.
- `first_order_only` (`TINYINT(1) DEFAULT 0`): Restricts coupon to customers with zero prior non-cancelled orders.
- `allowed_payment_modes` (`VARCHAR(255)`): Optional payment restriction (e.g., `ONLINE`, `COD`).
- `restricted_to_user_id` (`INT NULL`): Optional single-account lock (used for Support Apology coupons, Spin rewards, and Referral rewards).
- `reward_type` (`VARCHAR(32) DEFAULT 'standard'`): Supports `standard`, `free_shipping`, `coupon_credit`, and `referral_wallet`.
- `status` (`VARCHAR(20) DEFAULT 'active'`) & `is_active` (`TINYINT(1) DEFAULT 1`): Synchronized together on every write and status toggle.
- `expires_at` & `expiry_date` (`DATETIME`): Synchronized together on every write.
- `signature_sha512` (`VARCHAR(128)`): 512-bit cryptographic integrity hash of the coupon rules.

### 2.2 Immutable Redemption Ledger (`coupon_redemptions` Table)
- Columns: `id`, `coupon_id`, `coupon_code`, `user_id`, `order_id`, `order_number`, `discount_amount`, `order_subtotal`, `reward_type`, `status` (`'redeemed'` | `'reversed'`), `ip_address`, `user_agent`, `signature_sha512`, `redeemed_at`, `reversed_at`.
- Unique Composite Key: `uk_coupon_order (coupon_id, order_id)` + Indexes on `(coupon_id, user_id, status)` and `(coupon_code, user_id, status)`.
- **Atomic Checkout Enforcement (`models/orderModel.js` -> `createOrder`)**:
  1. Locks the `coupons` row with `SELECT ... FOR UPDATE` inside the database transaction.
  2. Verifies active status, start/expiry window, global `usage_limit`, `restricted_to_user_id`, `first_order_only`, `allowed_payment_modes`, and minimum order subtotal.
  3. Queries `coupon_redemptions` + non-cancelled `orders` for `user_id` and blocks checkout if `userRedemptions >= per_user_limit` (default `1`).
  4. Increments `coupons.used_count` and writes a SHA-512 signed row into `coupon_redemptions`.
- **Automatic Cancellation / Return Reversal (`models/orderModel.js` -> `updateOrderStatus`)**:
  - When an order transitions to `cancelled` or `returned`, its `coupon_redemptions` record is marked `status = 'reversed'` and `coupons.used_count` is decremented (`GREATEST(0, used_count - 1)`), allowing the customer to use their coupon again on a future valid order.

## 3. Omnichannel AI Concierge & `@BhumiveraBot` Telegram Architecture

### 3.1 Order & Tracking Reference Normalization (`services/aiSupportTools.js` & `services/aiSupportOrchestrator.js`)
- `stripOrderPrefix(raw)` strips `BHVM`, `BHV`, `ORD`, `#`, and punctuation so inputs like `BHVM815899599`, `#815899599`, `815899599`, `#20`, and courier tracking numbers (`shipments_logistics.tracking_number` or `orders.tracking_number`) resolve the exact order in `orders` and `shipments_logistics`.
- Every order card returned by `aiSupportTools.js` includes a direct clickable `trackingUrl` (`https://www.bhumivera.com/track-order?order=BHVM<orderNumber>`).

### 3.2 Complete A-to-Z Conversational Intent Coverage (`services/aiSupportOrchestrator.js`)
- Handles:
  - **Greetings & Help Menus**: `hi`, `hello`, `hey`, `namaste`, `/start`, `/help`, `menu`.
  - **Single-Word & Conversational Order Intents**: `order`, `orders`, `my orders`, `order history`, `track`, `status`, `where is my order`, `BHVM815899599`, `#20`.
  - **Returns, Replacements & Refunds**: `return`, `replace`, `exchange`, `refund`, `damaged`, `wrong item` — automatically lists recent orders for logged-in/linked users or prompts for the `BHVM...` order number + email/phone to create an instant RMA.
  - **Order Cancellations**: `cancel`, `cancel order` — self-service cancellation for unshipped (`pending`/`confirmed`/`processing`) orders with automatic stock and coupon restoration.
  - **Coupons, Offers & Wallet**: `coupon`, `coupons`, `promo`, `discount`, `wallet`, `points`, `loyalty`.
  - **Product Catalog Search & Shareable Links**: `link`, `share link`, `product`, `buy`, `recommend`, `price` — returns product cards with direct shareable URLs (`https://www.bhumivera.com/product/<slug>`).
  - **E-Warranty & Authenticity**: `warranty`, `serial`, `authentic`, `genuine` — checks serial authenticity or provides `https://www.bhumivera.com/warranty-registration`.
  - **Human Escalation**: `agent`, `human`, `executive`, `supervisor`, `manager` — escalates the session to `/support` and `/superadminsupport`.

### 3.3 Telegram Customer Correlation & Resilient Delivery (`services/telegramSupportService.js`)
- Automatically correlates a Telegram user (`tg_<chatId>`) with their Bhumivera `user_id` when:
  1. They open `@BhumiveraBot` via the website deep link (`/start web_<sessionToken>`).
  2. They send a `BHVM...` order number or email/phone that matches a customer order.
  3. Their Telegram username/name matches a recent active web support session.
- Once linked, `@BhumiveraBot` remembers `session.userId` across turns so `my orders`, `return`, `coupons`, and `wallet` work seamlessly inside Telegram.
- Resilient Telegram message sender automatically retries without Markdown parse mode if special characters in product/customer names trigger a Telegram parse error.

## 4. Role-Based Access Control (RBAC) & Industry-Standard Defaults

- **Loyalty Redemption Cap**: Default `max_redemption_percent` is **45%** (`models/loyaltyTierModel.js`, `utils/loyaltyPolicy.js`).
- **Support Role Benchmarks**:
  - **Support Executive (`agent` / L1)**: Max **10%** one-time apology coupon per customer; ₹0 wallet credit; cannot cancel orders or delete chats.
  - **Support Supervisor (`supervisor` / L2)**: Max **12%** one-time apology coupon per customer; max **₹150** one-time goodwill wallet credit; can cancel eligible orders.
  - **Support Manager (`manager` / L3)**: Max **15%** one-time apology coupon per customer; max **₹250** one-time goodwill wallet credit; can manage L1/L2 staff.
  - **SuperAdmin (`superadmin`)**: Up to **50%** coupons with no per-customer issuance cap; up to **₹2,000** wallet credit; exclusive permission to permanently delete `resolved`/`closed` chat transcripts.
