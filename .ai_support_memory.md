## 2. Storefront Navigation, Order Cancellation & Atomic Refund Ledger Logic
1. **Storefront CTA Routing (`Explore the Collection`)**:
   - `App.jsx` registers `/shop`, `/products`, `/collections`, and `/category/:slug` to render `<Shop />`.
   - `MiniCart.jsx` invokes `navigate('/products')` alongside `setIsCartOpen(false)` when empty-cart CTAs are clicked.
   - `PremiumHome.jsx`, `HeroSection.jsx`, `CategoryCard.jsx`, and `Impact.jsx` route directly to `/products` or `/collections`.
2. **SuperAdmin-Exclusive Order Cancellation**:
   - **Customer & Bot Restriction**: Customers cannot self-cancel orders once `Confirmed`, `Processing`, or `Shipped`, and cannot cancel via the chat bot (`DELETE /api/orders/:id` and `POST /api/orders/:id/cancel` return `403 SUPERADMIN_EXCLUSIVE_CANCELLATION` for non-SuperAdmins).
   - **Support Restriction**: L1/L2/L3 Support agents (`/support`) cannot cancel orders. `aiSupportTools.js` (`cancel_order`) and `aiSupportModel.js` (`cancelSupportOrder`) strictly verify `adminbhumivera27@gmail.com` or `superadmin` role.
   - **SuperAdmin Execution**: Only `adminbhumivera27@gmail.com` (via `/superadmin/controlcentre` with 6-Digit Step-Up Action Passcode verification or authenticated SuperAdmin token) can execute order cancellations.
3. **Atomic Refund & Wallet Restoration Ledger (`services/walletRefundLedgerService.js`)**:
   - Executed inside a single `BEGIN ... COMMIT` MySQL transaction with `SELECT ... FOR UPDATE` row locking:
     - Restores product stock (`products.stock`) and variant stock (`product_variants.stock`).
     - **Bhumivera Wallet / Credits (`WALLET`)**: Immediately credits `wallets.balance` (`users.wallet_balance`) and/or `referral_wallets.balance` for any deducted spendable/referral credits, inserts `wallet_transactions` and `referral_transactions` rows, and logs an immutable `wallet_refund_ledger` entry (`CREDITED_TO_WALLET`) with `balance_before`, `balance_after`, and `sha512_audit_hash`.
     - **UPI / Gateway (`UPI_GATEWAY`)**: Marks `orders.payment_status = 'refund_initiated'` (or `'refunded'`) and records the gateway refund reference in `wallet_refund_ledger` (`GATEWAY_REFUND_INITIATED`) so zero funds vanish.

## 3. Anti-Spam Chat Architecture & Human-Like Concierge Escalation Flow
1. **Two-Tier Chat Visibility & DDoS Protection**:
   - Removed the `"+"` (Create New Chat) button from `SupportAssistant.jsx` to prevent session-flooding attacks.
   - **Tier 1 — Public General Inquiry Bot (Unauthenticated / Zero Orders)**: Persistent `Bhumivera Client Concierge` window answering general questions (botanical ingredients, how to join Bhumivera, shipping policies, terms & conditions, brand story). Strictly rate-limited per IP/session and blocked from creating database support tickets (`403 ORDER_REQUIRED_FOR_LIVE_SUPPORT`).
   - **Tier 2 — Dedicated Order Support Chat (Verified Buyers Only)**: Unlocked only when the authenticated customer has `>= 1` placed order in the `orders` table (`GET /api/support/verified-buyer-status`). Reuses a single persistent thread per customer/order (`GET /api/support/sessions` checks for an existing open session before inserting).
2. **3-Step Customer Verification & Callback/Email Escalation Flow**:
   - Never auto-creates a ticket on keywords like `"human"`, `"associate"`, or `"cancel order"`.
   - **Step 1 (`POST /api/support/escalation/verify-order`)**: Validates `Order ID` + `Registered Email or 10-Digit Phone` against the `orders` and `users` tables and issues an HMAC-SHA256 `verificationToken`.
   - **Step 2 & 3 (`POST /api/support/escalation/submit`)**: Prompts: *"Our specialist team will reach out to you within 12 hours. Would you prefer to receive our update via Email or a Direct Phone Call?"*
     - **Email**: Confirms email address + query details.
     - **Direct Phone Call**: Validates 10-digit phone number + preferred callback slot (`Morning 10 AM–1 PM`, `Afternoon 1 PM–5 PM`, `Evening 5 PM–8 PM`).
     - Creates a single structured record in `support_escalation_tickets`.

## 4. Unified Master Control Centre (`/superadmin/controlcentre`) & Fortress Security
- **Zero Client-Side Credential Leaks**: Removed all on-screen OTP displays, auto-fill credential buttons, and client-side password constants from the React bundle.
- **First-Time Onboarding (`adminbhumivera27@gmail.com`)**:
  - When `superadmin_security_vault.is_onboarded = 0`, allows initial sign-in via `adminbhumivera27@gmail.com` + live 5-minute 6-digit Email OTP (`POST /api/superadmin/controlcentre/auth/request-otp` -> `POST /api/superadmin/controlcentre/auth/verify-onboarding-otp`).
  - Forces the **Security Vault Setup Wizard** (`POST /api/superadmin/controlcentre/auth/complete-vault-setup`) to configure Primary Master Password, Secondary Vault Password, 3 Custom Security Questions & Answers, and 6-Digit Master Action Passcode.
- **Standard Multi-Factor Login (`POST /api/superadmin/controlcentre/auth/login`)**:
  - Simultaneously verifies on the backend: Authorized Email (`adminbhumivera27@gmail.com`) + 5-min Email OTP (max 3 attempts) + Primary Master Password + Secondary Vault Password + 1 Randomly Selected Security Question Answer + 6-Digit Master Action Passcode.
- **Step-Up Action Passcode (`X-Action-Passcode`)**:
  - Required and verified on the backend (`requireStepUpPasscode`) for all state-changing operations (order cancellation/refunds, RBAC permission changes, staff creation, module pause/resume, escalation resolution).
- **Cryptographic Storage (`utils/fortressCrypto.js`)**:
  - Hybrid Scrypt (`N=16384, r=8, p=1`) + PBKDF2-HMAC-SHA512 (`210,000` iterations) with unique 32-byte per-field salts and constant-time comparison (`crypto.timingSafeEqual`).
  - AES-256-GCM + SHA-512 HMAC authenticated encryption for security questions/vault metadata.
  - HTTP-Only, `Secure`, `SameSite=Strict` session cookies + `X-CSRF-Token` validation.
- **Single-Master Orchestration, 108-Module Card-Grid & Dynamic RBAC Matrix**:
  - Orchestrates all 5 portals (`Storefront`, `Maison Executive Suite`, `Warehouse Portal`, `Customer Support Desk`, `SuperAdmin Support Center`) and 108 categorized modules.
  - Full-screen module workspace modal includes a **Dirty-State (Unsaved Changes) Guard** (*"You have unsaved changes. Would you like to Save before closing, Discard changes, or Cancel?"*).
  - Dynamic Per-User Permission Matrix across 11+ staff accounts and 108 modules with 4 states (`HIDDEN`, `READ_ONLY`, `WRITE_EDIT`, `FULL_CONTROL`) enforced at both the UI and API (`enforceDynamicRbacMatrix`) layers.
